# 언어·비전 모델 비교 기록

지금 서비스 모델(Qwen3-VL-32B-Instruct-FP8, 2025년 모델)을 새 모델로 바꾸기 위한 실측. 도구는 `../compare_models.py`, 시험 모델은 `../start_vllm_eval.sh`로 띄운다.
한 번 잴 때마다 아래에 표를 하나 더하고, 원본 기록(jsonl, 한 줄 = 요청 하나)을 이 폴더에 같이 둔다.

## 2026-11-12 — Qwen3.8-27B-FP8 vs Qwen3-VL-32B-Instruct-FP8

환경
| | A: 지금 서비스 | B: 후보 |
|---|---|---|
| 모델 | Qwen/Qwen3-VL-32B-Instruct-FP8 (통짜 32B) | Qwen/Qwen3.8-27B-FP8 (통짜 27B, 2026-08 공개, 받은 크기 29GB) |
| 자리 | GPU0, 8201, 메모리 50%, max-num-seqs 4, **서비스 요청과 같이 돌고 있음** | GPU1, 8202, 메모리 32%(약 44GB 늘어남), max-num-seqs 8, 이 시험만 |
| vLLM | 0.32.0 (`~/vllm_exp/.venv`) | 같음 |
| 생각 모드 | 없음 | `chat_template_kwargs.enable_thinking=false`로 끔 |

입력: 발화 분석 8개, 질문 답변 4개(망고 커리 가짜 해설 자료), 장면 해설 1개(cam540.mp4 10~24초 사진 8장, 사슴 닮은 동물·펭귄·얼음판, 대사 없음).
프롬프트는 `server.py`의 INTENT_SYSTEM·ANSWER_SYSTEM·DESCRIBE_SYSTEM 그대로. temperature 0.

| 항목 | A 32B | B 3.8-27B |
|---|---|---|
| 발화 분석 정답 | 8/8 | 8/8 |
| 발화 분석 JSON | 8/8 | 8/8 |
| 발화 분석 시간(중앙값) | 0.29초 | 0.28초 |
| 질문 답변 시간(중앙값) | 0.24초 | 0.24초 |
| 장면 해설 1개 | 7.94초 (출력 477토큰) | **3.15초 (출력 206토큰)** |
| 장면 해설 JSON | 맞음 | 맞음 |
| 장면 해설 1개 동시 | 6.5초, 73 토큰/초 | 2.64초, 78 토큰/초 |
| 4개 동시 | 9.32초, 202 토큰/초 | 3.98초, 200 토큰/초 |
| 8개 동시 | 18.67초, 203 토큰/초 | 4.77초, 324 토큰/초 |
| 실패 | 0 | 0 |
| 한자 섞임 | 0자 | 0자 |
| `<think>` 섞임 | 0 | 0 |

읽는 법
- 글자를 뽑는 속도(토큰/초)는 1·4개 동시에서 거의 같다. B가 장면 해설에서 2.5배 빠른 것은 **답을 절반 이하 길이로 쓰기 때문**이다.
- 8개 동시는 공정하지 않다: A는 max-num-seqs 4라 나머지 4개가 줄을 섰고 서비스 요청과 GPU0을 나눠 썼다.
- 질문 답변: 둘 다 자료에 없는 이름은 지어내지 않았다. A는 정해진 문구 "그건 해설 자료에 없어요"를 그대로 썼고, B는 "해설 자료에 그 사람의 이름이 나와 있지 않아요"로 풀어 써서 **UNANSWERABLE 문구와 다르다**. `app/internal_api.py:251`이 이 문구가 들어 있는지로 answerSource(UNANSWERABLE)를 정하고, 다른 장면 안내(`seek.py`)도 여기에 기대므로, 바꾸기 전에 프롬프트를 더 세게 하거나 판단 방법을 고쳐야 한다. B는 "넣었어"처럼 반말이 한 번 섞였다.
- 장면 해설(사진과 대조): A는 펭귄에 "큰 파란 눈, 붉은 리본"처럼 사진에 없는 것을 붙였고 B는 "흰 배와 검은 등"으로 맞게 짧게 썼다. 대신 B의 "펭귄이 꽃을 들고 있다"는 틀림(꽃 옆에 엎드려 있음). A의 "식물이 끊긴다"는 맞는 내용(마지막 사진에서 꽃이 부러짐). 장면 하나라 품질은 아직 판단 못 함.

아직 안 잰 것: 영상 전체 줄거리(/story, 출력 1,500~5,000토큰), 영상 통째 해설(/describe_video), 번역, 긴 영상 두 편 동시.
