# 언어·비전 모델 비교 기록

지금 서비스 모델(Qwen3-VL-32B-Instruct-FP8, 2025년 모델)을 새 모델로 바꾸기 위한 실측. 도구는 `../compare_models.py`, 시험 모델은 `../start_vllm_eval.sh`로 띄운다.
한 번 잴 때마다 아래에 표를 하나 더하고, 원본 기록(jsonl, 한 줄 = 요청 하나)을 이 폴더에 같이 둔다.

## 2026-11-12 — Qwen3.8-27B-FP8 vs Qwen3-VL-32B-Instruct-FP8

환경
| | A: 지금 서비스 | B: 후보 |
|---|---|---|
| 모델 | Qwen/Qwen3-VL-32B-Instruct-FP8 (통짜 32B) | Qwen/Qwen3.8-27B-FP8 (통짜 27B, 2026-08 공개, 받은 크기 29GB) |
| 자리 | GPU0, 8201, 메모리 50%, max-num-seqs 4, **서비스 요청과 같이 돌고 있음** | GPU1, 8202, 메모리 32%(약 44GB 늘어남), max-num-seqs 8, 이 시험만 |
| vLLM | 0.32.0 (`~/vllm_exp/.venv`) | 같음 |
| 생각 모드 | 없음 | `chat_template_kwargs.enable_thinking=false`로 끔 |

입력: 발화 분석 8개, 질문 답변 4개(망고 커리 가짜 해설 자료), 장면 해설 1개(cam540.mp4 10~24초 사진 8장, 사슴 닮은 동물·펭귄·얼음판, 대사 없음).
프롬프트는 `server.py`의 INTENT_SYSTEM·ANSWER_SYSTEM·DESCRIBE_SYSTEM 그대로. temperature 0.

읽는 법
- 글자를 뽑는 속도(토큰/초)는 1·4개 동시에서 거의 같다. B가 장면 해설에서 2.5배 빠른 것은 **답을 절반 이하 길이로 쓰기 때문**이다.
- 8개 동시는 공정하지 않다: A는 max-num-seqs 4라 나머지 4개가 줄을 섰고 서비스 요청과 GPU0을 나눠 썼다.
- 발화 분석·질문 답변은 챗봇이 Gemini를 쓰기로 해서 참고용이다(2026-11-12 결정). 아래 UNANSWERABLE 문제도 H200 모델을 바꾸는 데 걸림돌이 아니다.
- 질문 답변: 둘 다 자료에 없는 이름은 지어내지 않았다. A는 정해진 문구 "그건 해설 자료에 없어요"를 그대로 썼고, B는 "해설 자료에 그 사람의 이름이 나와 있지 않아요"로 풀어 써서 **UNANSWERABLE 문구와 다르다**. `app/internal_api.py:251`이 이 문구가 들어 있는지로 answerSource(UNANSWERABLE)를 정하고, 다른 장면 안내(`seek.py`)도 여기에 기대므로, 바꾸기 전에 프롬프트를 더 세게 하거나 판단 방법을 고쳐야 한다. B는 "넣었어"처럼 반말이 한 번 섞였다.
- 장면 해설(사진과 대조): A는 펭귄에 "큰 파란 눈, 붉은 리본"처럼 사진에 없는 것을 붙였고 B는 "흰 배와 검은 등"으로 맞게 짧게 썼다. 대신 B의 "펭귄이 꽃을 들고 있다"는 틀림(꽃 옆에 엎드려 있음). A의 "식물이 끊긴다"는 맞는 내용(마지막 사진에서 꽃이 부러짐). 장면 하나라 품질은 아직 판단 못 함.

## 2026-11-12 (2) — 줄거리·영상 통째 해설·번역 (H200에서 실제로 중요한 일)

챗봇은 Gemini를 쓰므로 H200 모델을 고르는 기준은 이 셋이다. 도구 `../compare_long.py`(server.py가 vLLM에 보내는 요청을 그대로 흉내).
환경은 위와 같음(A는 서비스와 함께 GPU0, B는 GPU1 단독).
- 영상: `cam540.mp4`(Caminandes 애니메이션 2분 30초, 대사 없음), `ivana640.mp4`(배구 선수 인터뷰 예능 1분 7초, 한국어 대사)
- 영상 통째 해설 프롬프트·스키마: 노트북에서 `app.pipeline.video`의 `build_video_prompt`·`video_schema`로 만든 지금 서비스 그대로(소리·대사 칸은 비움), temperature 0.2, 최대 10,000토큰

- 번역: `experiments/mango_en.json` 12조각, 조각마다 앞뒤 2개 맥락, 동시 8개, 반복 벌점 1.1, 틀리면 RETRY_HINT로 한 번 더

내용을 사진·원문과 대조한 것
- 영상 해설: A는 장면을 영상 끝까지 쓰지 않았다(두 영상 모두, 동시 실행에서도 같음). 등장인물 이름을 "lama", "penguin"처럼 영어로 쓰고 근거를 "영상 제목"이라 적었다(제목은 Caminandes라 근거 아님). B는 끝까지 덮고, 이름 근거가 없으니 name을 비우고 basis "화면"으로 썼다(규칙대로).
- 줄거리: A는 라마를 "황소"라 불렀다. B는 "카마"라는 없는 이름을 지었다(what에는 "갈색 라마"). ivana640에서 A는 "애유나"라는 이름을 지어냈다. B는 "코트비 진행자"로 썼다. 둘 다 이름 붙이기는 약하다.
- B의 줄거리는 ```json 울타리로 감싸 나온다. server.py의 json_block이 첫 `{`부터 마지막 `}`까지 꺼내므로 그대로 읽힌다.
- 번역: A는 재료 이름이 틀렸다(cinnamon → "육계수", cloves → "팥배", tuna → "토너비"). B는 계피·정향·참치·강황으로 맞다. "1 half teaspoons of salt"는 A "1티스푼", B "두 작은술"로 둘 다 틀렸다(1.5작은술). B가 문장 중간에서 끝나는 조각(2, 6번)은 원문 조각이 거기서 끊겨 있어서 맞는 번역이다. B 1번 조각은 마침표 없이 이어 썼다.
- 입력 토큰이 B가 적은 것은 A에만 `--mm-processor-kwargs`(영상 프레임 크기)를 준 탓이다. 같은 설정으로 다시 재면 B 시간이 조금 늘 수 있다.

정리: 세 작업 모두 B가 더 빠르고(영상 해설 30~40%, 줄거리·번역 약 2배), 영상 해설이 영상 끝까지 가며 번역 용어가 정확하다. 이름 짓기는 둘 다 약하다.
