# 내 정보 · S15P31D101-310

`/me`의 임시 화면을 계정 정보, 설정, 로그아웃, 비밀번호 변경·탈퇴 모달로 교체한다.

## 디자인과 접근성

- [Figma 내 정보 수정](https://www.figma.com/design/6NaOLfDXCAezgQM0GNacI5/Audisay?node-id=514-1648)을 기준으로 계정 정보 카드와 두 줄 설정 카드를 배치했다. 행 사이 구분선은 넣지 않는다.
- 기존 헤더·안내 띠·색/글씨 토큰을 재사용한다. Figma 원본은 수정하지 않는다.
- 이름·이메일·회원 등급·인증 날짜는 서버 응답을 사용한다. 인증 날짜는 한국 시간으로 표시하며 임의 날짜나 비밀번호 길이를 노출하지 않는다.
- 공통 `Dialog`, `PasswordField`, `Button`을 사용한다. 비밀번호 변경은 현재 비밀번호, 탈퇴는 취소에 진입한다. Esc로 닫기, 내부 초점 유지, 호출 버튼 복귀를 제공한다.
- 입력 오류와 설명을 해당 필드에 연결한다. 비밀번호 붙여넣기·자동 완성을 허용하고, 공백을 허용하지 않는 서버 비밀번호 규칙을 검사한다.
- 처리 중 중복 제출과 취소를 막는다. 닫거나 성공하면 입력값과 비밀번호 보기 상태를 초기화한다.
- 재생 설정은 시청 화면의 기존 설정 창을 재사용한다. 실패 시 원복하고 성공 안내를 하지 않는다. 사용법 다시 듣기는 기존 `/tutorial/1`로 이동한다.

## API

[Notion API 명세서](https://app.notion.com/p/API-659979d8e2cb82849c508101840c085c)와 저장소의 `UserController`, `UserService`, 요청 DTO를 함께 확인했다. 공통 API 기본 경로는 `/api/v1`이다.

| 기능           | 요청                           | 결과                                                    |
| -------------- | ------------------------------ | ------------------------------------------------------- |
| 계정 정보      | `GET /users/me`                | 이름·이메일·등급·인증 날짜                              |
| 비밀번호 변경  | `PATCH /users/me/password`     | `currentPassword`, `newPassword`; 현재 기기 로그인 유지 |
| 회원 탈퇴      | `DELETE /users/me`             | `password`; 성공 후 토큰·사용자·캐시 정리               |
| 재생 설정      | `GET/PATCH /users/me/settings` | 기존 SettingsProvider와 설정 창 재사용                  |
| 오늘 남은 횟수 | `GET /users/me/quota`          | 기존 횟수 컴포넌트 재사용, 실패 시 재시도               |
| 로그아웃       | `POST /auth/logout`            | 토큰·사용자·캐시 정리 후 시작 화면 이동                 |

탈퇴 성공 뒤 별도 로그아웃 API는 호출하지 않는다. 서버가 이미 세션과 RefreshToken 쿠키를 만료시킨다. 일반 로그아웃의 통신 실패 시 로컬 세션은 정리하고 서버 세션 정리가 확인되지 않았음을 안내한다.

## 검증 범위

- 자동 테스트: 계정 조회·오류·재시도, 입력 검증, 비밀번호 불일치·통신 오류·성공, 중복 제출 방지, 모달 초점, 탈퇴 취소·실패·성공, 세션·캐시 정리, 설정 저장·실패 원복, axe 검사.
- 실제 테스트 계정: 내 정보·설정·남은 횟수 조회, 모달 열기·Esc·초점 복귀를 확인했다. 실제 계정의 비밀번호 변경과 탈퇴는 실행하지 않았다.
- 1440·720·360 너비와 글자 크기 5단계·고대비에서 본문 가로 넘침을 확인했다. 기존 공통 헤더의 좁은 화면 대응은 이 작업 범위 밖이다.
- 실제 NVDA·센스리더 낭독 검사는 별도로 필요하다. 자동 검사만으로 접근성 준수를 확정하지 않는다.
